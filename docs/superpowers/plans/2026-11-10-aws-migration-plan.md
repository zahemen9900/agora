# Agora AWS Migration Implementation Plan

**Goal:** Restore Agora on AWS, preserve existing data and API keys, and keep the entire AWS account below $30/month at the supported load.

**Architecture:** One x86-64 EC2 `t3a.small` runs Caddy, the API, Redis, and the trusted sandbox broker through Compose. Private S3 holds durable records; the broker launches network-isolated sibling containers on the host Docker daemon. GitHub OIDC publishes three ECR images and a release bundle, then deploys through SSM; SSM SecureString supplies secrets out of band.

**Tech Stack:** Python 3.11, FastAPI, boto3/botocore, S3, Redis AOF, Docker Engine/Compose v2, Caddy, Amazon Linux 2023, EC2/IAM/ECR/SSM, Terraform, GitHub Actions, Vercel, existing WorkOS/model-provider/Solana integrations.

**Spec path:** `docs/superpowers/specs/2026-11-10-aws-migration-design.md` (read alongside this plan; the corrections below supersede its unsafe details).

## Global Constraints

- AWS account `866160682016`, region `us-east-1`; local provisioning uses existing `gsl-admin` SSO, refreshed interactively. No static AWS credentials.
- Monthly AWS account bill **under $30**, including unrelated spend (approximately $0.27 so far this month). No automatic size upgrade, NAT, ALB, managed Redis, paid interface endpoints, or paid VPC encryption controls.
- Billable provisioning and copying GCS to S3 are already approved. This document does not authorize exceeding the ceiling, destroying GCP resources, publishing secrets, or deleting old data.
- GCP `agora-ai-1190` is suspended but GCS/Secret Manager are readable. Export `agora-ai-1190-agora-data`: expected baseline 83 objects, approximately 2.3 MB; re-inventory before copying.
- Default HTTPS hostname is `agora-api.<EIP>.nip.io`; use a real domain only if supplied. Preserve the EIP across host replacement.
- Repository `https://github.com/zahemen9900/agora.git`, deployment branch `main`. Preserve unrelated changes (`Untitled` and the untracked design existed at review time).
- No application schema/auth-flow changes, key regeneration, arbitrary string replacement, Terraform-held secret values, or runtime dependence on GCP.
- Implement task-by-task using `executing-plans` or an explicitly approved delegation workflow. This review only writes this plan; no provisioning, implementation, or commits were performed.

## Review Focus

1. Concurrent append/read/delete: use the ETag belonging to the bytes read, retry fresh reads, and never silently downgrade CAS (Task 2).
2. Real browser PUT: exact signed Content-Type/length, S3 CORS, missing/oversized/overwritten upload, and protected source ownership (Task 3).
3. Sibling Docker execution: identical host/container paths, non-root writable output, bounded memory/disk/stdout, and cancellation cleanup (Tasks 5, 8).
4. Restart/multi-workspace pressure: Redis really reachable, host-wide admission includes benchmarks/recovery, and expired leases do not permit duplicate writers (Tasks 4, 8, 13).
5. Cutover/rollback: preserve pepper and key hashes, rewrite only recognized records, and recover from proxy disconnects or a failed release without reverting production data (Tasks 6, 10–14).

## Independent review: corrections and implementation gates

| Severity | Finding in the actual repository | Required correction |
|---|---|---|
| Critical | `api/store.py:453,711` converts generations to integers. A HEAD after a GET could pair old bytes with a newer ETag. | Remove **both** casts. Capture ETag from the same `GetObject` response as Body; do not refresh a missing token and then write old bytes. S3 version IDs are not `IfMatch` tokens. |
| Critical | `sandbox_runner_service/app.py:177–181` passes container-local paths to the **host** daemon. | Critical | `AGORA_WORKSPACE_CONCURRENT_TASK_RUNS` is per workspace (`tasks.py:651`); benchmark execution has only per-run locks (`benchmarks.py:3433`). | Add host-wide execution admission across tasks, benchmarks, and recovery. Workspace=2 alone does not bound host load. |
| High | Runner uses root runtime containers, unbounded `communicate()`, an unbounded writable host directory, and an unbounded semaphore wait queue. | Bound all four; the Docker socket makes the broker host-root-equivalent. Do not claim it is a strong hostile-tenant boundary. |

**Go/no-go:** Code/IaC implementation can proceed, but **public cutover must stop** if real S3 CAS/browser PUT tests, secret/pepper verification, certificate issuance, or the 2 GB mixed-load/reboot tests fail. A permanent `t3a.medium` costs roughly $36–39/month all-in and is **not** an authorized fallback. Standard-credit throttling, single-host downtime, shared-kernel sandbox risk, and third-party DNS remain deliberate limitations.

### Decisions

- **Builder calls:** x86-64 `t3a.small`, CPU credit mode `standard`, one API worker, host-wide active-run cap 2 and pending-run cap 8, workspace cap 2, one sandbox, bounded tmpfs, ECR digest releases, default AWS-managed SSM key, local protected Terraform state for initial provisioning. Reduce active-run cap to 1 if required by measured load; do not silently restrict supported task/agent shapes.
- **User calls before cutover:** acceptance of shared-kernel untrusted execution on the credential-bearing single host; supply a domain only if desired or if nip.io issuance fails; choose implementation workspace; provide/use a privately held existing API key for preservation testing; confirm notification recipient and emergency shutdown policy. No need to re-ask permission for approved billable resources or GCS copy.
- **User calls if gates fail:** reduced supported load/features versus another architecture. A larger host, second sandbox machine, new domain purchase, GCP destruction, and recurring cost above $30 require a new decision; an upgrade cannot override the hard ceiling.
